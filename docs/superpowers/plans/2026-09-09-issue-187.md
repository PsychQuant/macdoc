# CLI 測試 binary 選擇 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after approval.

**Goal:** CLI 測試預設使用與測試編譯組態一致的 binary，不因其他組態檔案存在而改道。
**Architecture:** 在 CLITestHelper 內分離無副作用的選擇／驗證函式；保留 binaryPath 呼叫介面但允許拋錯。標準 debug/release 用編譯組態選擇，自訂建置目錄或外部 binary 透過明確環境變數指定。
**Tech Stack:** Swift 5.9、Foundation、XCTest、SwiftPM。
**Spec:** Issue #187 及 [Diagnosis](https://github.com/PsychQuant/macdoc/issues/187#issuecomment-5590698583)。

### Decision Points

1. 選「編譯組態 + 顯式 override」，不選 mtime 比較。時間戳不能證明產物對應目前 source。
2. 新增測試用 `MACDOC_TEST_BINARY`，只接受非空絕對路徑；不存在或不可執行即 throw，不 fallback。相對路徑、空值皆 fail-loud，避免 cwd 造成差異。
3. 標準路徑為 repoRoot/.build/debug/macdoc 或 release/macdoc，由測試 target 的 DEBUG 條件決定。自訂 scratch path 必須設定 override，不猜 SwiftPM 私有目錄布局。
4. 不在 resolver 執行 swift build；建置是 test invocation 的責任。`--skip-build` 仍可能測到同組態旧產物，README 必須明說。
5. 路徑資訊寫入測試 runner stderr，不加進子程序 CLIResult.stdout/stderr；每次 run 記錄一行，不引入共用 once-state／鎖。

#### Task 1 — 純 resolver 與測試

- [ ] 先加入 resolver 測試；尚未定義函式時為編譯 RED，定義介面後確認錯誤選路 assertion 為行為 RED。
- [ ] 在 CLITestHelper 新增以下介面及最小實作；錯誤 type 採可斷言的 enum。

```swift
enum BinarySelectionError: Error, Equatable {
    case invalidOverride(String)
    case unavailable(String)
}

static func resolveBinaryURL(
    repoRoot: URL,
    configuration: String,
    environment: [String: String],
    isExecutable: (String) -> Bool
) throws -> URL {
    let candidate: URL
    if let override = environment["MACDOC_TEST_BINARY"] {
        guard !override.isEmpty, override.hasPrefix("/") else {
            throw BinarySelectionError.invalidOverride(override)
        }
        candidate = URL(fileURLWithPath: override)
    } else {
        candidate = repoRoot.appendingPathComponent(".build")
            .appendingPathComponent(configuration)
            .appendingPathComponent("macdoc")
    }
    guard isExecutable(candidate.path) else {
        throw BinarySelectionError.unavailable(candidate.path)
    }
    return candidate
}
```

測試不改動真實 .build，用以下模式提供存在集合：

```swift
func testDebugDoesNotPreferRelease() throws {
```

#### Task 2 — 接回呼叫鏈

- [ ] binaryPath 使用 throwing getter；DEBUG 下 configuration="debug"，否則 "release"。

```swift
static var binaryPath: String {
    get throws {
        #if DEBUG
        let configuration = "debug"
        #else
        let configuration = "release"
        #endif
        return try resolveBinaryURL(
            repoRoot: repoRoot, configuration: configuration,
            environment: ProcessInfo.processInfo.environment,
            isExecutable: { FileManager.default.isExecutableFile(atPath: $0) }
        ).path
    }
}
```

### Test Plan

| Case | 預期 |
|---|---|
| debug + debug/release 皆可執行 | debug |
| release + debug/release 皆可執行 | release |
| debug 缺席、release 存在 | unavailable，不 fallback/skip |
| override 可執行 | override |
| override 空／相對／不可執行 | 明確 error |
| runner 路徑日誌 | 不改 CLIResult，TokenCount 精確 stderr 測試仍成立 |
| 自訂 scratch path | 明確 override 選到剛建置的產物 |
| timeout caller | 與修改前同一 timeout／回收語意 |

### Risks & Mitigations

- 把 property 改為 throwing 可能漏直接 caller：以 rg 搜尋 binaryPath，再編譯整個 test target。
- 標準 .build 假设不適用自訂路徑：用 override 明確處理，不 silent fallback。
- 同組態舊產物與 skip-build 不由此案證明 freshness；實作驗收必須先 build。
- 若 DEBUG 定義在實際 SwiftPM release/debug 測試不符，停止並修正組態判定，不能以兩個路徑輪流搜尋掩蓋。
