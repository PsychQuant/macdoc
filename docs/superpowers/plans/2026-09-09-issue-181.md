# swiftify 替代路徑提示 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after approval.

**Goal:** 讓缺 paraId 文件在預設 reverse 與 swiftify 文件都能發現 paragraphs-only，並明白其保真代價。
**Architecture:** 沿用 rawReasons 的精確根因判斷；保留 coverage stdout，僅在非 coverage 路徑補 stderr 提示。文件分根因列選項，不改預設 full-fidelity。
**Tech Stack:** Swift、XCTest、SwiftPM、Markdown plugin 文件與 JSON manifests。
**Spec:** Issue #181 與 [Diagnosis](https://github.com/PsychQuant/macdoc/issues/181#issuecomment-5590698053)；既有 `openspec/specs/ooxml-script-transcode/spec.md`。

- 保留 coverage stdout 的既有格式與提示，預設 exit code／寫檔保護不變。
- Commit subject 尾端 (#181)，不得使用自動關閉 issue 語法。

### Decision Points

- 用 rawReasons["word/document.xml"] == "paragraph-no-paraId" 判斷，不看 aggregate 0%。
- 非 coverage 印一行 stderr；coverage 只保留目前 stdout 長提示，避免同次輸出兩份說明。

- plugin 文件可先發布既有 paragraphs-only 用法；新 stderr 行為明列「尚未發布，需含此修正的 CLI」。binary_version 保留已驗證的發布版本。

### Test Plan

| Case | stdout | stderr |
|---|---|---|
| 缺 paraId、不帶 coverage | 空 | 單一精簡提示與既有寫入成功 |
| 缺 paraId、帶 coverage | 原 coverage 長提示 | 不重複精簡提示 |
| 有 paraId 或其他 raw 根因 | 維持既有契約 | 不出 paragraphs-only 建議 |
| paragraphs-only 或 sidecar | 維持既有契約 | 不出 full-fidelity 根因提示 |
| slot／full-fidelity 回歸 | 不因提示改動 source/export 語意 | 錯誤與寫入訊息仍正確 |

### Risks & Mitigations

- 產生無效 XML 不一定走到 parse-error raw reason：負向 reason 判斷以單元測試明確注入，端到端只用可穩定建立的 fixture。
- 不在提示內容加上 coverage 專用的「上面的百分比」，避免無 coverage 時語意錯誤。
- plugin 文件新版本不代表 CLI 新 binary 已發布，需明列未發布限制，不能改高 binary_version 觸發不存在的下載。
- #187 未合入時既有 test helper 可選舊 release；驗收前檢查實際 executable，不只看 swift test 的建置成功。
