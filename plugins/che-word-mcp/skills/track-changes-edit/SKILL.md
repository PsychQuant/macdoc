# track-changes-edit — 用追蹤修訂改別人的文件

## 這是什麼

別人請你「直接修改」他的文件時，修訂本身就是你交給他的說明：他會逐處決定接受或拒絕。
所以修訂要**少**、要**準**、每一處都要讓他看得出**為什麼**。

這個 skill 管兩件事：

1. **改不改**：哪些地方有資格改成修訂，判斷要怎麼查證。
2. **怎麼標**：逐字的修訂、附在修訂上的註解、改完的驗證。

工具面的限制（`insert_text_as_revision` 目前不包 `<w:ins>`、插在段尾、不帶格式）追蹤於
PsychQuant/che-word-mcp#276、#292、#296。修好之前用本 skill 附的腳本（見〈寫入〉）。

## Step 0：建立任務清單（強制）

動手前用 `TaskCreate` 建下列任務，完成一項標一項。**靜默完成 = 違規。**

| # | subject（直接複製） | 類型 | 跳過條件 |
|---|-------------------|------|---------|
| 1 | 列出文件中每一處要核對的陳述，以及各自對應的來源 | 機械 | 不可跳過 |
| 2 | ⚠️ 逐處讀來源原文判斷是否相符（讀段落，不憑搜尋結果） | **判斷** | **不可跳過** |
| 3 | 分類：可直接修訂（封閉兩類）／改用註解提問／不動 | 判斷 | 不可跳過 |
| 4 | 寫修訂 spec：每組修訂附註解，註解引用來源原文 | 機械 | 沒有要修訂的地方 |
| 5 | 執行腳本，輸出到新檔名 | 機械 | 沒有要修訂的地方 |
| 6 | 驗證：腳本的自動檢查＋讀回修訂與註解＋打開文件目視 | 驗證 | 不可跳過 |
| 7 | 回報：改了哪幾處、各自依據、哪些留給作者決定 | 機械 | 不可跳過 |

**為什麼強制**：第 2 步最容易被跳過。搜尋結果看起來已經回答了問題，於是直接進第 4 步寫修訂。
這個 skill 存在的原因，正是搜尋結果曾經兩次被當成結論，兩處修訂都錯了，事後撤回。

## 規則一：可以直接改成修訂的，只有這兩類

以下是**封閉列舉**，只有這兩類；**不得依性質相似類推第三類**。

| # | 類別 | 邊界條件 |
|---|------|---------|
| 1 | **與來源牴觸的事實** | 你讀過來源中對應的段落，該段落**字面上**與文件說法不同。註解要引用那段原文與位置。從來源「推得出」的結論不算牴觸 |
| 2 | **錯字** | 單字層級的打錯（同音誤植、漏字、多字）。註解寫「錯字」即可 |

**其餘一律不改成修訂，改用註解提問**，由文件作者決定。這包括：刪除或合併段落、改寫語氣或
風格、調整用詞一致性、文法上的偏好、補充你認為更好的說法。這些是編輯決定，作者拒絕時你的
修訂就成了噪音；用註解問，他接受的話自己改，或請你改。

## 規則二：搜尋定位，閱讀定案

查證時的四條紀律（來源：PsychQuant/claude-code-logos 的 `skill-best-practices` Practice 7）：

1. **搜尋只用來找位置。** `grep`、`rg`、`search_text` 告訴你段落在哪裡；判斷要 `Read` 那個段落。
2. **截斷的搜尋結果不是證據。** `| head`、`| tail`、`grep -m N` 之後「沒看到」不等於「來源沒寫」，決定性的那一行可能就在截斷處之後。
3. **主張「決定了」「確認了」的，讀來源的結論段全文。** 來源中轉述他人立場或說法的段落，不是來源自己的結論；第一個符合預期的句子也不是。
4. **說「來源沒有寫」之前**，換其他說法再搜一次，並讀周圍的段落。

註解裡引用的原文必須是你讀過的那段，寫出位置（檔名＋節或行）。

## 規則三：逐字標記

- 修訂只標**不同的字**。把「甲」改成「乙」，修訂就是刪「甲」插「乙」，不是刪掉整句再插入整句。
- 一處修訂若同時涉及刪與插，兩者都附在同一則註解下。
- 插入的字沿用插入位置原本的格式（字型、顏色）。

## 寫入

腳本：`scripts/track_revise.py`（標準庫，無相依套件）。

```bash
python3 scripts/track_revise.py spec.json 原檔.docx 新檔名.docx
```

`spec.json`：

```json
{
  "author": "你的名字",
  "initials": "縮寫",
  "revisions": [
    {
      "paragraph": "<段落的 w14:paraId>",
      "comment": "依來源第三節：「……」，故「甲」改為「乙」。",
      "changes": [{"old": "段落中唯一出現的原文片段", "new": "改後片段"}]
    }
  ],
  "comments": [
    {"find": "某段落中唯一出現的文字", "text": "這段是否保留，想請您決定；我沒有修改。"},
    {"paragraph": "<paraId>", "anchor": "要提問的那一句", "text": "來源寫「……」，此處是否改寫，想請您決定；我沒有修改。"}
  ]
}
```

- 段落用 `paragraph`（`w14:paraId`，可用 che-word-mcp 的 `get_paragraphs` 查）或 `find`（只出現在一個段落的文字）指定。
- 註解不帶 `anchor` 時掛在整段；帶 `anchor` 時只掛在段落中**恰好出現一次**的那段文字上，文字本身不變。段落很長、只想問其中一句時用 `anchor`。
- `old` 必須在該段落中**恰好出現一次**；寫長一點直到唯一。
- 每組修訂**必須**有 `comment`，沒有就拒絕執行。
- 輸出路徑已存在就拒絕；不會寫回原檔。

腳本在寫檔前自動檢查，任何一項失敗就**什麼都不寫**：

- 全部拒絕後，每一段文字都等於原稿；
- 全部接受後，被改的段落等於預期的文字；
- 修訂與註解以外的段落逐位元組不變；
- 所有 XML part 格式正確；含 DOCTYPE／ENTITY 宣告的文件直接拒絕。

目標段落裡若有定位字元、分行、欄位、圖片這類非純文字的 run，腳本會拒絕並說明，這種段落在
Word 裡手動改。

## 驗證（腳本通過之後仍要做）

1. 讀回修訂與註解：che-word-mcp 的 `get_revisions`、`list_comments`（Direct mode，帶 `source_path`）。逐一確認每處修訂都有對應註解、註解內容與你讀到的來源一致。
2. 用 Word 或 Pages 打開新檔，看修訂標記的位置與格式。
3. 回報時列出：每處修訂的前後文字與依據；用註解提問、沒有修改的地方；查證後確認無誤、沒有改的部分。

## 不做

- 不刪段、不改風格、不改作者沒問的地方（規則一）。
- 不憑截斷的搜尋結果下判斷（規則二）。
- 不覆寫原檔，不覆寫既有的輸出檔。
- 不把修訂理由只寫在信裡或對話裡：理由要在文件中、附在修訂上，作者審閱時才看得到。
