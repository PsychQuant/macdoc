## 1. Implementation (sequential — types reference each other)

These four tasks each create or modify a file under `packages/ooxml-swift/`. Sequential because the test file (1.4) needs the reducer + cache + error types to exist, and the cache (1.3) consumes the reducer's static functions. Tasks 1.1 through 1.4 share three cross-cutting decisions that drive their structure: **Decision 1: Reducer is an enum-namespace with static functions, not a struct/class** (each entry point is a `public static func` on the `OperationReducer` enum), **Decision 2: `XmlTree` mutation happens on a deep copy of `base`** (the reducer NEVER mutates the caller's input — `XmlTree.deepCopy()` and `XmlNode.deepClone()` are added as `internal` methods on the v0.30.0 types), and **Decision 8: Tree mutations use existing v0.30.0 primitives, not new ones** (each Operation case maps to existing `XmlNode` API calls; no new low-level mutation primitives are introduced).

Add `internal func deepClone() -> XmlNode` to `XmlNode` that recursively constructs a new XmlNode tree (clones all attributes, all children recursively, copies `prefix`/`localName`/`namespaceURI`/`textContent`/`processingInstructionTarget`/`libraryUUID`; sets `sourceRange = nil` and `isDirty = true` on the clone since synthesized nodes are by definition dirty).
