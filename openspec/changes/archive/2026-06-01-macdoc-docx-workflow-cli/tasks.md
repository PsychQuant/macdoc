## 4. Edit planning + execution (`Sources/DocxWorkflowLib/EditPlanner.swift`, `Executor.swift`)

- [x] 4.1 Create `Sources/DocxWorkflowLib/EditPlanner.swift` exposing `internal struct EditPlanner` with method `func compile(_ step: Step, anchorRef: ParagraphRef, doc: LensDocument) -> CompileResult` where `CompileResult` is an enum: `.functional(any Edit)`, `.pending(stepType: String, tracker: String)`. The planner SHALL return `.functional` for the 8 runtime-functional step types in §2.1 and `.pending(stepType: <name>, tracker: "ooxml-swift#71")` for the 4 Phase 2c-pending step types. Covers spec.md Requirement "Phase-2c-pending step types compile but warn at runtime". **Behavior**: for `.insertParagraph`, the planner returns `.functional(WordEdit.applyInsertParagraph(after: anchorRef, content: step.content))`; for `.insertImage`, the planner returns `.pending(stepType: "insert_image", tracker: "ooxml-swift#71")`. **Verify**: `swift test --filter EditPlannerTests` passes.

- [x] 4.2 Create `Sources/DocxWorkflowLib/Executor.swift` exposing `public struct Executor` with `public func apply(manifest: Manifest, baselineURL: URL, outputURL: URL, warnHandler: (String) -> Void) throws -> ExecutorResult`. The Executor SHALL: (1) read the baseline via `try LensDocument(reading: baselineURL)`, (2) for each step in `manifest.steps` resolve its anchor against the current document state (sequential resolution per spec.md Requirement "Executor applies steps in manifest order"), (3) compile the step via EditPlanner, (4) if `.functional` apply the Edit via `lens.apply(edit)` and update the working `lens` reference, (5) if `.pending` invoke `warnHandler("warn: step type '<name>' has no Reducer support yet (tracker: ooxml-swift#71); skipping")` and continue without applying, (6) after all steps emit via `lens.emit(to: outputURL)`. Anchor failures and Edit failures SHALL propagate unchanged; no partial output SHALL be written. Covers spec.md Requirement "Executor applies steps in manifest order" + "Phase-2c-pending step types compile but warn at runtime" + (in the modified word-builder-swift capability) "Layer 3 consumers compose multi-step authoring flows via the re-exported Edit surface" — this Executor is the canonical Layer 3 consumer cited in that Requirement. Respects design.md Non-Goals (no archive-first auto-snapshot, no MCP transport changes — Phase 1 stays inside `DocxWorkflowLib` + the upcoming `Docx` subcommand). **Verify**: `swift test --filter ExecutorTests` (tests in §6.3) all pass.

- [x] 4.3 Define `public struct ExecutorResult` in `Sources/DocxWorkflowLib/Executor.swift` with fields `appliedStepCount: Int`, `skippedPendingStepCount: Int`, `skippedStepTypes: [String]`. Returned from `Executor.apply` to support `plan` and `apply` subcommand reporting. **Behavior**: a manifest with 3 functional + 1 pending step produces `appliedStepCount=3, skippedPendingStepCount=1, skippedStepTypes=["insert_image"]`. **Verify**: covered by `swift test --filter ExecutorTests.testMixedRunPopulatesResult`.
