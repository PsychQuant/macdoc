## 1. Implementation (sequential — same module, types reference each other)

These five tasks each create a new file under `packages/ooxml-swift/Sources/OOXMLSwift/OpLog/` (tasks 1.1-1.4) or `packages/ooxml-swift/Tests/OOXMLSwiftTests/` (task 1.5). They are sequential because later types reference earlier types and the test file (1.5) needs all four production files to exist. Same-module Swift compile resolves cross-file refs at type-check time, but running the unit tests requires every type to be present.

All §1 tasks share two cross-cutting decisions: **Decision 6: File organization — new `OpLog/` module under `Sources/OOXMLSwift/`** (each task adds its file inside the new `OpLog/` directory, mirroring the existing `Tree/` module organization) and **Decision 7: No `WordDocument.operationLog` field in this change** (none of these tasks modifies `Document.swift`; integration is deliberately deferred so Phase 2b/2c can decide between Document-owned vs. SyncOrchestrator-owned).

- [x] 1.1 Apply **Decision 1: `Operation` is a Swift enum with associated-value cases for typed ops + an `unknown` fallback for forward-compat** and **Decision 5: `JSONValue` is a custom enum, not `[String: Any]`** to create `packages/ooxml-swift/Sources/OOXMLSwift/OpLog/Operation.swift`. File contains: (a) `public enum Operation: Equatable, Sendable` with all 21 cases listed in design.md Decision 1 (16 element-level + 4 tree-node-level + 1 `unknown(opType:payload:)` forward-compat); (b) payload structs `ParagraphPayload`, `TablePayload`, `RunPayload`, `RunFormatPayload` — minimal field sets carrying just what each typed setter needs (text, optional styleId, optional rPr fields, etc.); (c) `public indirect enum JSONValue: Equatable, Sendable, Codable` with cases `null`, `bool(Bool)`, `int(Int)`, `double(Double)`, `string(String)`, `array([JSONValue])`, `object([String: JSONValue])`. Run `swift build` in `packages/ooxml-swift/` to verify compile-clean. Implements the **Operation taxonomy covers full OOXML mutation surface** requirement.

- [x] 1.2 Apply **Decision 2: `ElementID` is a value type wrapping a `String` derivation** to create `packages/ooxml-swift/Sources/OOXMLSwift/OpLog/ElementID.swift`. File contains: `public struct ElementID: Equatable, Hashable, Sendable, Codable` with `public let raw: String` stored property and three initializers — `init?(node: XmlNode)` walking the priority chain (`w14:paraId` → `w:bookmarkId` → `w:id` → `r:id` → `w14:textId` → `libraryUUID` → returns nil), `init(libraryUUID: UUID)` producing `"lib:\(uuid.uuidString)"`, `init(rawString: String)` accepting any String verbatim. The `init?(node:)` SHALL byte-align with `XmlNode.stableID`'s output format (i.e., produce the exact same string the XmlNode property returns for the same node). Run `swift build` to verify. Implements the **ElementID derivation rules** requirement.

- [x] 1.3 Apply **Decision 3: `OperationLog` is a value type (struct) with append-only mutating API** to create `packages/ooxml-swift/Sources/OOXMLSwift/OpLog/OperationLog.swift`. File contains: (a) `public struct OperationLog: Equatable, Sendable` with `public private(set) var entries: [LogEntry] = []`, `init()`, `mutating func append(_ op: Operation, source: OpSource, opID: UUID = UUID(), at timestamp: Date = Date())`, `mutating func batch(_ source: OpSource, label: String? = nil, _ body: (inout OperationLog) throws -> Void) rethrows`. The batch helper SHALL emit a `batchBegin(label:)` op before invoking body and a `batchEnd` op after body returns normally. (b) `public struct LogEntry: Equatable, Sendable, Codable` with `opID: UUID`, `op: Operation`, `source: OpSource`, `timestamp: Date`. (c) `public enum OpSource: String, Equatable, Sendable, Codable` with cases `.swift` and `.word`. Run `swift build` to verify. Implements the **Append-only operation log**, **Operation IDs are unique and stable**, **Source attribution for every operation**, and **Batch transactions for grouped mutations** requirements.

- [x] 1.4 Apply **Decision 4: JSONL format is one JSON object per line, lossy fields excluded, unknown ops carry their full payload** to create `packages/ooxml-swift/Sources/OOXMLSwift/OpLog/OperationLog+JSONL.swift`. File extends `OperationLog` with: `public func encodeJSONL() -> Data` emitting one JSON object per line per `LogEntry` separated by `\n` (Unix LF), each line containing `op_id`, `ts` (ISO-8601 UTC), `source`, `op_type` (case discriminator string) followed by op-specific fields in declaration order. For `.unknown(opType:, payload:)` cases, the payload `JSONValue` SHALL be merged into the line with object keys sorted lexicographically for byte-equal round-trip. `public static func decodeJSONL(_ data: Data) throws -> OperationLog` parsing newline-delimited JSON objects back into a log; lines missing any of the four required fields SHALL throw `OperationLogJSONLError.malformedLine(lineIndex: Int)`; unknown `op_type` strings SHALL decode to `.unknown(opType:, payload:)` carrying the entire JSON object minus the four required fields as the payload. Define the `OperationLogJSONLError` enum in this file. Run `swift build` to verify. Implements the **JSONL on-disk format** and **Forward-compatible log format** requirements.
