## 2. Security envelope (`R/escape.R`)

Implements design.md Decision 4: typed escape-on-construction (no `paste0()` of Swift code from user data). Closes the HIGH-severity finding from closed PR #96. Supports design.md Non-Goals (no string-interpolation API).

- [x] 2.1 Create `R/escape.R` exposing `internal_escape_swift_string(s)` that takes a single R character vector and returns a Swift-string-literal-safe escape. Escapes per spec.md Requirement "Typed escape-on-construction prevents Swift code injection from user data": `"` → `\"`, `\` → `\\`, `\n` → `\\n`, `\r` → `\\r`, `\t` → `\\t`, control chars 0x00-0x1F and 0x7F → `\\u{<hex>}`, U+2028 / U+2029 → `\\u{2028}` / `\\u{2029}`. **Behavior**: input `'A\\B"C'` produces output `'A\\\\B\\"C'` (R-string repr; the underlying bytes match what Swift expects in source). **Verify**: `swift test --filter test-escape.R` (test in §6.1) passes.

- [x] 2.2 Create `R/escape_helpers.R` exposing `internal_swift_literal_string(s)` that wraps escaped output in surrounding `"..."` to produce a complete Swift string literal. Composition: `internal_swift_literal_string(s) == paste0('"', internal_escape_swift_string(s), '"')`. Centralizes the construction so future audit can `grep` for any string-literal emission going through this single chokepoint. Implements design.md Decision 4: typed escape-on-construction (centralized helper as the single chokepoint). **Verify**: `swift test --filter test-escape.R::test_swift_literal_wraps_in_quotes` passes.

- [x] 2.3 [P] Audit guard: add a CI script `tools/check-no-direct-paste.sh` that `grep`s `R/*.R` for `paste0(.*"WordEdit\\|paste0(.*"OOXMLEdit\\|paste0(.*"LensDocument\\|paste0(.*"DocxReader\\|paste0(.*"DocxWriter` patterns. Any match fails CI. Covers spec.md Requirement scenario "Injection attempt is neutralized" by preventing the construction-side bug from being introduced. **Verify**: `bash tools/check-no-direct-paste.sh` exits 0 on the Phase 1 codebase.

## 5. Emitter (`R/emit.R`, `R/edit_planner.R`, `R/export.R`)

Implements design.md Decision 2: emit `WordEdit` / `OOXMLEdit` cases DIRECTLY, not through a Swift shim module. Implements design.md Decision 5: tidyverse `%>%` pipeline API + `wb_*` naming convention. Implements design.md Decision 6: `wb_export()` writes a SELF-CONTAINED `.swift` source file.

The emitted output is the canonical Layer 4 consumption pattern cited in the modified word-builder-swift spec Requirement "Layer 4 callers consume the re-exported Edit surface via emit-direct, not via parallel Swift shim modules" — this task is the concrete Layer 4 emitter that Requirement anchors against.

- [x] 5.1 Create `R/edit_planner.R` exposing internal `plan_step(step)` that takes a single step record (from §4.x) and returns a Swift-code-string for that step. Branches on `step$type`: functional step types produce direct `OOXMLEdit.*` / `WordEdit.*` calls; pending step types produce `try?`-wrapped calls with `// ooxml-swift#71 follow-up` comments. ALL string literals in the emitted Swift go through §2.2 `internal_swift_literal_string()`. Covers spec.md Requirements "Runtime-functional step emits non-`try?` Edit call" + "Pending step emits `try?`-wrapped Edit call with tracker comment". **Verify**: `swift test --filter test-edit-planner.R` passes; golden-file comparison against `tests/testthat/golden/*.swift` snippets.

- [x] 5.2 Create `R/emit.R` exposing internal `emit_full_swift(state, output_path)` that assembles the full Swift source file: header comment block (per spec.md Requirement "Generated Swift source declares Layer 4 caller annotation"), `import Foundation` + `import WordBuilderSwift`, document construction preamble (empty `WordDocument` + seed paragraph + round-trip to temp file + LensDocument(reading:) per word-builder-swift v1.0.0 examples), step-by-step `lens.apply(...)` chain (using §5.1 `plan_step()` output), final `lens.emit(to: outputURL)`. The `output_path` is the docx output URL embedded in the emitted Swift (NOT the `.swift` file path; that's handled by §5.3). **Verify**: `swift test --filter test-emit.R` passes; emitted source structure matches the spec's Layer 4 emission scenario.

- [x] 5.3 Create `R/export.R` exposing `wb_export(state, path)` that writes the §5.2-assembled Swift source to the file at `path`. Resolves `state$output` if NULL by defaulting to `sub("\\.swift$", ".docx", path)`. Validates the parent directory exists; creates if missing. Covers spec.md Requirement "wb_export writes a self-contained runnable Swift source file". **Behavior**: `wb_document() %>% wb_paragraph("Hi") %>% wb_export("/tmp/out.swift")` writes a file at `/tmp/out.swift` whose body imports WordBuilderSwift + applies the paragraph step. **Verify**: `swift test --filter test-export.R` passes.
